### 🟠 Существенное (2)

#### 1. [Типы данных и форматы] 2 Структура данных CDM  ·  _правило_

> | 1 | FIELD_REGION_NAME | string | Название региона | Определяется как последнее значение region_name за месяц для абонента: сначала по (lac, cell), затем fallback-логика (см. алгоритм). |

- **Что неясно:** В таблице 5 пол(е/я/ей) без признака обязательности (NOT NULL / NULLABLE) — официальное требование кейсодателя к описанию витрин. Пример: «| 1 | FIELD_REGION_NAME | string | Название региона | Определяется как последнее значение region_name за месяц для абонента: сначала по (lac, cell), затем fallback-логика (см. алгоритм). |»; ещё 4 строк(а/и) с той же проблемой.
- **Почему важно для разработки:** Без явного NOT NULL/NULLABLE разработчик не знает, для каких полей нужно обрабатывать пустое значение, и это придётся выяснять по каждому полю отдельно.
- **Что уточнить или добавить:** Проставить NOT NULL или NULLABLE у каждого поля таблицы (не только у одного примера).
- **Вопрос аналитику:** Для каких из перечисленных полей допустим NULL, а для каких — нет?
