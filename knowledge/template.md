## Алгоритм обработки потока
Детальное пошаговое описание алгоритма обработки потоковых данных:
фильтрация, трансформация, обогащение.

- **Шаг 1. Фильтрация данных** — описание условий фильтрации данных из источника.
- **Шаг 2. Обогащение данных** — описание алгоритма обогащения данных.
- **Шаг 3. `<Наименование шага 3>`** — описание преобразований, выполняемых на шаге 3.

Если какой-то из типовых шагов (фильтрация / обогащение / иная обработка) для
конкретного потока не нужен, это **обязательно** прописывается явной
формулировкой «не применимо» — раздел не должен молча отсутствовать (см.
`correction_patterns.md`, пункт 5). *(вариант для витрины-агрегата: раздел
называется «Алгоритм расчёта» и состоит из шагов вида «Шаг 1. Выбор
пользователей», «Шаг 2. Определение вендора» и т.д.)*

## Требования к агрегату (доп. блок для витрин-агрегатов)

В примерах документации по витринам-агрегатам вместо/в дополнение к
нефункциональным требованиям встречается отдельная таблица:

| Требование | Значение |
| --- | --- |
| Регламент расчёта | например, ежемесячно |
| Период агрегации | например, календарный месяц |
| Глубина данных | с какой даты хранится история |
| Региональная агрегация | да/нет, по какому разрезу |
| Часовой пояс | например, UTC |
| Поле партиционирования | имя поля |
| Обновление | полная перезагрузка периода / upsert / инкремент |

Отсутствие этой таблицы (или её текстового эквивалента) для витрины-агрегата —
повод для замечания категории `incremental` или `schedule_sla`.
