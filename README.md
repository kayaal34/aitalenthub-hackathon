# ТЗ-Ревьюер

**AI-инструмент для предварительного ревью технических заданий** на разработку
новых потоков и витрин данных.

Кейс МТС (продукт NET). Инструмент получает текст ТЗ и возвращает структурированный
результат предварительной проверки: перечень фрагментов, которые могут быть
непонятны разработчику, с объяснением причины, рекомендацией и вопросом для
аналитика. Инструмент **не заменяет аналитика** и не выносит решение о готовности
документа — он подсвечивает места, требующие внимания, до передачи задачи в
разработку.

---

## Что он делает

На вход — текст ТЗ (`.md`, `.txt`, `.docx`). На выход — отчёт:

1. **Перечень замечаний.** Для каждого: раздел ТЗ, дословная цитата, критичность
   (`blocker` / `major` / `minor`), что неясно, почему это важно для разработки,
   что уточнить, вопрос аналитику.
2. **Покрытие шаблона.** Каких разделов канонического шаблона ТЗ не хватает.
3. **Индекс готовности** (0–100) и текст-ориентир — вспомогательные, не вердикт.

### Как формируются замечания

| Слой | Что делает | Работает без LLM |
| --- | --- | --- |
| Разбор документа | делит ТЗ на разделы (Markdown / нумерация / КАПС), читает таблицы из `.docx` | да |
| Покрытие шаблона | сверяет разделы ТЗ с каноническим шаблоном (`knowledge/template.md`) | да |
| Эвристики | заглушки/`TODO`, расплывчатые формулировки, поле без типа, расчёт без формулы, аббревиатуры без глоссария | да |
| LLM-ревью | анализ по доменной рубрике из 19 категорий + few-shot на паттернах корректировок разработчиков | нет |

Если LLM недоступен или ключ не задан — инструмент автоматически работает в
офлайн-режиме (слои 1–3).

## Установка

```bash
git clone <repo-url>
cd tz-reviewer
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Минимальный набор (офлайн-режим, без демо): `pip install pydantic python-dotenv python-docx`.

## Настройка LLM

Скопируйте `.env.example` в `.env` и заполните. Инструмент провайдер-независимый:

| Сценарий | `TZR_PROVIDER` | `TZR_MODEL` | `TZR_BASE_URL` | ключ |
| --- | --- | --- | --- | --- |
| Anthropic (Claude) | `anthropic` | `claude-opus-5` (дешевле: `claude-sonnet-5`) | — | `ANTHROPIC_API_KEY` |
| OpenAI | `openai` | `gpt-4o-mini` | — | `OPENAI_API_KEY` |
| OpenRouter | `openai` | `openai/gpt-4o-mini` и др. | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` |
| Локально (Ollama) | `openai` | `llama3.1` и др. | `http://localhost:11434/v1` | любой непустой |
| Локально (vLLM / LM Studio) | `openai` | имя модели | `http://localhost:8000/v1` | любой непустой |
| Внутренний контур МТС | `openai` | имя модели | адрес прокси | выданный ключ |
| Без LLM | `offline` | — | — | — |

`TZR_PROVIDER=auto` (по умолчанию) выбирает режим по наличию ключа и `base_url`.

## Запуск

### Веб-демо (Streamlit)

```bash
streamlit run app.py
```

Вставьте текст ТЗ, загрузите файл или выберите пример → «Проверить ТЗ».

### CLI

```bash
# офлайн-ревью примера, отчёт в stdout
python cli.py examples/tz_flow_raw.md --offline

# с LLM (настройки из .env), отчёт в файл
python cli.py path/to/ТЗ.docx --format md --out out/review.md

# принудительно указать провайдера и модель
python cli.py examples/tz_flow_raw.md --provider openai --model gpt-4o-mini

# форматы: md (по умолчанию), html, json
python cli.py examples/tz_flow_raw.md --offline --format html --out out/review.html
```

### Из Python

```python
from tz_reviewer import review_document, Settings
from tz_reviewer.report import to_markdown

report = review_document(open("ТЗ.md", encoding="utf-8").read(), settings=Settings())
print(to_markdown(report))
```

## Структура репозитория

```
tz_reviewer/            ядро (пакет, не зависит от интерфейса)
  document.py           загрузка .md/.txt/.docx, разбиение на разделы
  knowledge.py          загрузка шаблона / чек-листа / few-shot / паттернов корректировок
  rubric.py             доменная рубрика ревью (19 категорий)
  heuristics.py         офлайн-правила
  prompts.py            системный и пользовательский промпты (RU)
  llm.py                провайдер-независимый клиент (Anthropic / OpenAI-совместимый)
  analyzer.py           оркестрация пайплайна
  scoring.py            индекс готовности и вердикт
  report.py             рендер в Markdown / HTML / JSON
knowledge/              база знаний (редактируйте под свои ТЗ)
  template.md           канонический шаблон ТЗ
  checklist.md          расширенный чек-лист
  correction_patterns.md типовые корректировки разработчиков
  few_shot_examples.json примеры «фрагмент → замечание»
examples/               демонстрационные ТЗ (сырое / доработанное / витрина)
app.py                  Streamlit-демо
cli.py                  командная строка
docs/                   описание проекта, продуктовые материалы, пример отчёта
presentation/           презентации (генератор + .pptx)
tests/                  pytest (эвристики + смоук пайплайна в офлайне)
```

## Как повысить качество ревью

Замечания тем предметнее, чем ближе база знаний к вашим реалиям:

- дополните `knowledge/correction_patterns.md` реальными правками разработчиков;
- добавьте пары «фрагмент → замечание» в `knowledge/few_shot_examples.json`;
- поправьте `knowledge/template.md` под ваш шаблон ТЗ;
- при необходимости отредактируйте категории в `tz_reviewer/rubric.py`.

## Ограничения

- Качество LLM-анализа зависит от модели и качества входного текста; возможны
  ложноположительные замечания.
- ТЗ ожидается как связный текст (не скан).
- Пост-проверка того, что цитата дословно есть в тексте, и подсветка фрагмента
  в исходном ТЗ — в плане на финальную версию.
