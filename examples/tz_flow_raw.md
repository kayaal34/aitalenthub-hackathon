# Техническое задание: поток загрузки данных об услугах абонентов

Версия: 0.3 (черновик). Автор: аналитик команды NET.
Данные в примере нейтральные, реальные имена систем и полей заменены.

## 1. Цель

Нужно сделать новый поток, который будет собирать данные об услугах абонентов
и складывать их в витрину для аналитиков. Витрина используется для отчётности
и должна обновляться регулярно.

## 2. Источник

Данные берём из системы биллинга, таблица услуг. Там есть всё, что нужно:
идентификатор абонента, услуга, дата подключения, статус, стоимость и ещё
несколько технических полей. Данные приходят каждый день.

## 3. Приёмник

Складываем в витрину `mart_services`. Поля примерно такие же, как в источнике,
плюс добавляем дату загрузки. Тип полей стандартный.

- abonent_id
- service
- date_start
- status
- price
- load_date

## 4. Логика загрузки

Загрузка инкрементальная, по дате. Берём новые записи с момента последней
загрузки и добавляем их в витрину. Если запись уже была — обновляем её.
Старые данные не трогаем.

Если источник недоступен, загрузка пропускается и выполняется в следующий раз.

## 5. Трансформации

- Стоимость услуги пересчитывается в рубли и округляется стандартным образом.
- Активные услуги — это услуги со статусом, отличным от завершённого.
- Если у абонента несколько одинаковых услуг, берём последнюю.
- Поле `service` приводим к нормальному виду.
- Технические записи отфильтровываем.

## 6. Расписание

Поток должен работать каждый день и обновлять витрину к утру, чтобы аналитики
могли пользоваться свежими данными. Периодичность — ежедневно.

## 7. Историчность

Витрина отражает текущее состояние услуг абонента. Нужно, чтобы всегда было
видно актуальный статус.

## 8. Качество данных

После загрузки нужно убедиться, что данные загрузились корректно и их объём
адекватный. При проблемах — сообщить команде.

## 9. Пример

Абонент подключил услугу, потом сменил тариф. В витрине должно быть корректное
значение стоимости.

## 10. Прочее

Остальные детали (доступы, объёмы, обработка ошибок формата) — по аналогии с
существующими потоками. При необходимости уточним в процессе разработки.
