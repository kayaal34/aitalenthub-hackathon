# Техническое задание: поток загрузки данных об услугах абонентов

Версия: 1.0. Автор: аналитик команды NET. Статус: на ревью.
Данные в примере нейтральные, реальные имена систем и полей заменены.

## 1. Общая информация

- **Поток:** `flow_subscriber_services`
- **Потребители:** команда отчётности NET (ежедневные витрины услуг).
- **Связанные документы:** глоссарий показателей NET (ссылка), DDL витрины (приложение А).

## 2. Бизнес-контекст и цель

Поток формирует витрину `mart.subscriber_services` — актуальный и исторический
срез услуг абонентов для регулярной отчётности. В скоуп не входят: расчёт
выручки, тарифная детализация, витрины по устройствам.

## 3. Глоссарий

- **Услуга** — подключаемая абоненту опция из справочника `ref.service`.
- **Активная услуга** — услуга со `status_code` из множества {1, 2, 5}
  (`подключена`, `приостановлена оператором`, `в ожидании активации`).
- **Абонент** — идентификатор `subscriber_id` из системы биллинга.

## 4. Источник данных

| Параметр | Значение |
| --- | --- |
| Система | Биллинг (контур `prod`, реплика для чтения `billing_ro`) |
| Объект | `billing_ro.public.subscriber_service` |
| Способ | SQL-выборка по JDBC |
| Частота готовности | ежедневно, срез на 03:00 МСК, готов к 04:30 МСК |
| Полнота | полный срез активных и закрытых за последние 400 дней записей |
| Поле изменения | `updated_at` (timestamp, МСК) |

Справочник услуг: `ref.service` (`service_id`, `service_name`, `is_technical`),
обновляется еженедельно, берём актуальную версию на момент загрузки.

## 5. Целевой объект

Схема `mart`, таблица `subscriber_services`. DDL — приложение А.
**Гранулярность:** одна строка = одна услуга абонента в одном периоде действия
(SCD2). Партиционирование по `valid_from_date` (месяц), retention 5 лет.

| Поле | Тип | Обяз. | Источник / правило |
| --- | --- | --- | --- |
| subscriber_id | bigint | да | `subscriber_service.subscriber_id` |
| service_id | int | да | `subscriber_service.service_id` |
| service_name | varchar(200) | да | `ref.service.service_name` по `service_id`; если нет — `'UNKNOWN'` |
| status_code | smallint | да | `subscriber_service.status_code` |
| price_rub | numeric(12,2) | да | см. п.7.1 |
| valid_from | timestamp | да | момент вступления версии в силу (МСК) |
| valid_to | timestamp | нет | `NULL` для текущей версии, иначе `valid_from` следующей |
| is_current | boolean | да | `true` для последней версии ключа |
| load_id | bigint | да | идентификатор запуска загрузки |
| load_ts | timestamp | да | время загрузки (UTC) |

**Бизнес-ключ:** (`subscriber_id`, `service_id`, `valid_from`).
**Ключ актуальной версии:** (`subscriber_id`, `service_id`) при `is_current = true`.

## 6. Стратегия загрузки

- Инкремент по `updated_at`: берём записи с `updated_at > watermark`.
- **Watermark** — максимальный `updated_at` из предыдущей успешной загрузки,
  хранится в `meta.load_watermark`.
- **Окно перекрытия:** дополнительно перечитываем последние 2 суток (late data).
- **Идемпотентность:** повторный запуск за тот же период не создаёт дублей —
  запись сопоставляется по бизнес-ключу, при совпадении версия не создаётся.
- **Перезаливка периода:** запускается вручную дежурным аналитиком параметром
  `reload_from=<дата>`; зависимые витрины пересчитываются следом по регламенту R-12.
- При недоступности источника загрузка не выполняется, поднимается инцидент,
  следующий запуск делает полный дозабор по `updated_at` от старого watermark.

## 7. Трансформации

### 7.1 Расчёт `price_rub`

```
price_rub = round(source.price * fx_rate(source.currency, valid_from_date), 2)
```
- `fx_rate` — курс из `ref.fx_rate` на дату `valid_from_date`, режим округления
  half-up до 2 знаков;
- если `source.price` IS NULL → строка отбраковывается в карантин `dq.rejected`;
- если курс не найден → `price_rub = NULL`, флаг `dq_price_no_fx = true`.

### 7.2 Историчность (SCD2)

- Сравниваем пришедшую запись с текущей версией по (`status_code`, `price_rub`,
  `service_id`); при отличии — закрываем текущую (`valid_to = new.valid_from`,
  `is_current = false`) и добавляем новую.
- **Удаление в источнике** (запись пропала из полного среза за 400 дней и
  `status_code = 9`) → закрываем версию, `is_current = false`, новую не создаём.
- Изменения задним числом: если `new.valid_from` < `max(valid_from)` по ключу —
  строка идёт в `dq.backdated` для ручного разбора, в витрину не попадает.

### 7.3 Фильтры и дедупликация

- Исключаем услуги, где `ref.service.is_technical = true`.
- Исключаем `status_code = 0` (черновик).
- Дубликаты по (`subscriber_id`, `service_id`, `updated_at`): оставляем запись
  с максимальным `source_row_id`.

### 7.4 Соединения

- `subscriber_service` LEFT JOIN `ref.service` ON `service_id`
  (ожидаемо 1:1; при отсутствии справочной строки — `service_name = 'UNKNOWN'`,
  флаг `dq_service_missing = true`).

## 8. Контроли качества

| Проверка | Порог | Действие при нарушении |
| --- | --- | --- |
| Число строк за сутки vs среднее за 14 дней | отклонение > 40% | стоп загрузки, алерт |
| Уникальность бизнес-ключа | 100% | стоп загрузки |
| Доля `price_rub IS NULL` | > 2% | загрузка с алертом |
| Сверка `count(distinct subscriber_id)` с источником | расхождение > 0.5% | алерт |

## 9. Расписание и SLA

- Запуск ежедневно в 05:00 МСК, зависимость: успешное завершение `flow_ref_service`.
- SLA готовности витрины: 07:00 МСК.
- Политика повторов: 3 попытки с интервалом 20 минут, далее инцидент.

## 10. Объёмы

- Старт: ~120 млн строк активных услуг + ~40 млн закрытых за 400 дней.
- Прирост: ~1.5 млн изменённых строк в сутки.
- Перезаливка: максимум 400 дней истории.

## 11. Доступы и ПДн

- `subscriber_id` — псевдонимизированный идентификатор, не ПДн.
- Доступ к витрине: роль `mart_reader_net`.
- Чтение источника: сервисная учётная запись `svc_net_billing_ro` (только SELECT).

## 12. Пример «вход → выход»

Вход (2 версии одной услуги):
```
subscriber_id=1001, service_id=50, status_code=1, price=10, currency=USD, updated_at=2026-01-10 09:00
subscriber_id=1001, service_id=50, status_code=2, price=10, currency=USD, updated_at=2026-02-01 12:00
```
Выход в витрине (курс USD на 2026-01-10 = 90, на 2026-02-01 = 92):
```
1001, 50, 'Услуга A', 1, 900.00, 2026-01-10 09:00, 2026-02-01 12:00, false
1001, 50, 'Услуга A', 2, 920.00, 2026-02-01 12:00, NULL,               true
```
